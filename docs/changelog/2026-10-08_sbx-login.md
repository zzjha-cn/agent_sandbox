# 2026-10-08 · `sbx login`（M2-12）

## 一句话

把"第一次用要照抄一条 `docker run -it ... claude auth login`"换成一条命令，顺手把登录态做成可查、可退、可换账号。

## 为什么是它先做

M1 验收完之后 M2 的第一件事。理由是它**是新用户遇到的第一个台阶**：原来的流程要先 `sbx run` 失败一次、从报错里抄一条带 `-v sbx-home:/home/agent` 的 docker 命令、自己判断要不要加 `-e HTTPS_PROXY`。抄错一个参数，凭据就落到别的 volume 里，而且报错不会告诉你这件事。

## 做了什么

```bash
sbx login             # = sbx login claude，走一遍 claude auth login
sbx login --status    # 已登录：you@example.com · team · claude.ai
sbx login --logout    # 清掉 sbx-home 里的凭据
sbx login --force     # 已登录时也重新走一遍（换账号）
sbx login --console   # 用 Anthropic Console 账号（按量计费）
sbx login --email a@b.c
```

实现是一个临时容器：`docker run --rm [-it] --mount type=volume,source=sbx-home,target=/home/agent <镜像> claude auth`。

几个取舍：

- **镜像和 volume 都由这条命令负责准备好**。`sbx login` 会先 `Ensure` 镜像、再建 `sbx-home` / `sbx-cache`（按宿主机 UID/GID 设属主）。所以它可以是用户跑的第一条命令，不必先 `sbx run` 失败一次。为此把 `ensureVolumes` 里的共享 volume 部分拆成了 `ensureSharedVolumes`，`run` 和 `login` 共用。
- **这个容器不接 `sbx-proxy`**。它没有 Task，也就没有 Task 网络；配了 `network.upstream` 就注入 `HTTPS_PROXY` / `HTTP_PROXY`，否则直连。这是一条和"所有出网都过 squid"不同的路径，写在了 commands.md 和 design §7.1 里，不打算藏着。
- **Agent 名是参数，流程是表驱动的**。`sbx login [claude|codex]`，省略即 claude；`authCLIs` 这张表给每个 Agent 记四件事（怎么查登录态、怎么登、怎么退、怎么解析输出），加 codex 就是加一条，不动命令本身的分支。`codex` 现在在 `pendingAgents` 里，报错说的是"推迟到 M3-6"，和"不认识的 Agent"两条路径分开——前者是我们的进度，后者是你打错了。
- **和 `sbx upgrade` 一样不要求在 git 仓库里执行**，只 `loadConfig`，不 `Resolve` Workspace。
- `run` 里那段打印 docker 命令的 `loginHelp` 现在只说一句"先执行 `sbx login`"。对应的 `TestLoginHelpUsesUpstream`（断言帮助文本里有 `-e HTTPS_PROXY=`）已经没有意义，换成了 `TestAuthArgs`：代理注入的断言从帮助文本挪到了真正拼 docker 参数的地方。

## 登录态的解析

`claude auth status` 默认输出 JSON，**没登录时退出码是 1，但 JSON 照样打印**：

```json
{ "loggedIn": false, "authMethod": "none", ... }
```

所以 `agent.ParseStatus(out, execErr)` 的规则是：能解析出 JSON 就以 JSON 为准，`execErr` 只在解析不出来时才交出去（比如镜像里根本没有 claude）。顺手容忍了 JSON 前后多出来的提示行。`Runtime.LoggedIn`（`sbx run` 启动前的那次检查）也改成走这个函数，两处逻辑合成一处。

## 验证

- 真实 `sbx-home`：`sbx login --status` → `已登录：…`；`sbx login` → 打印同样一行并提示 `--logout` / `--force`，不重复走登录。
- 空 volume（`sbx-login-probe`，验完已删）：`claude auth status` 退出码 1 + `loggedIn:false` 的 JSON，解析正常；`claude auth login` 直接打印授权链接和 `Paste code here if prompted >`，**没有卡在首次启动的 TUI 对话框上**——也就是说登录流程不需要 preseed，这一点复核了 M0-1 的结论。
- `go test ./...` 全绿。

交互式登录本身（粘回授权码、凭据落盘）要人来完成，没有自动化验收。
